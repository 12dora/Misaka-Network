# 编码 AI 提示词模板

> 复制粘贴到 Claude Code / Cursor / 其他编码 AI 即可。
> 
> **核心思路：每次会话只让 AI 读相关文档，避免上下文爆炸。**

---

## 📌 启动会话提示词（每次开新对话都用这个）

```
你是「御坂网络」项目的开发者。这是一个 React + WebRTC 的 P2P 文件传输 Web APP。

【启动步骤】请按顺序执行：

1. 读取 docs/00-overview.md 了解整体架构
2. 读取 docs/PROGRESS.md 查看当前进度
3. 从 PROGRESS.md 中找到「当前会话焦点」未填写或下一个 ☐ 未完成的项目
4. 告诉我你计划本次完成哪些任务，然后等我确认

【关键原则】
- 不要一次读取所有文档。docs/ 下文件按功能拆分，只读你本次任务相关的
- 每个 docs/0X-*.md 都是独立模块，按 PROGRESS.md 中标注的「参考 0X-xxx.md」按需读取
- 完成任务后，必须更新 docs/PROGRESS.md：
  - 把 ☐ 改为 ☑（完成）或 ◐（进行中）
  - 在「当前会话焦点」记录本次实际完成的内容
  - 在「已知问题」记录遗留的 bug（如有）
  - 在「决策记录」记录关键技术决策（如有）
- 不要修改其他无关代码
- 不要安装 PROGRESS.md / 00-overview.md 没提到的依赖（除非必要，需说明原因）

【现在开始】
```

## 📌 继续会话提示词（同一会话内推进时）

```
继续。读取 docs/PROGRESS.md 看最新进度，然后告诉我下一步建议做什么。
```

## 📌 模块开发提示词模板

替换 `[模块名]` 和 `[文档编号]`：

```
本次任务：实现 [模块名]

请先读取以下文档：
- docs/PROGRESS.md（确认未完成项）
- docs/[文档编号]-xxx.md（模块规范）
- docs/01-design-system.md（如果涉及 UI）

完成后更新 docs/PROGRESS.md，把对应项标 ☑。
```

例：
```
本次任务：实现首页登录卡片

请先读取：
- docs/PROGRESS.md
- docs/02-pages-home.md
- docs/05-auth-identity.md
- docs/01-design-system.md

完成后更新 PROGRESS.md。
```

## 📌 会话结束提示词

```
本次会话结束。请：
1. 更新 docs/PROGRESS.md
2. 简短总结本次完成的内容（5 行内）
3. 列出下次会话应该优先做的 1-3 件事
```

## 📌 调试 / 修 bug 提示词

```
出现 bug：[描述]

请先读取 docs/PROGRESS.md 的「已知问题」，然后定位并修复。
修复后在 PROGRESS.md「已知问题」标记或删除。
```

---

## 📌 重要约定（提醒编码 AI）

如果编码 AI 偏离规范，可以贴这段：

```
请记住项目约定：
1. 所有 UI 文案使用 docs/01-design-system.md 的「术语对照表」
2. 颜色/字体使用 docs/01-design-system.md 的设计 token
3. 不要在服务端持久化任何数据，全部内存存储
4. 不要在 QR 中默认包含通行码
5. TURN 服务器默认禁用，仅用户手动配置后启用
6. 完成任务必须更新 PROGRESS.md
```

## 推荐工作流

```
Day 1 会话 1：脚手架 + 设计系统
Day 1 会话 2：信令服务器基础接口
Day 2 会话 1：首页 UI
Day 2 会话 2：身份系统打通（前后端联调）
Day 3 会话 1：WebRTC 连接建立
Day 3 会话 2：文件分片传输
Day 4 会话 1：网络页 UI
Day 4 会话 2：接收流程联调
...
```

每个会话 60-120 分钟为宜，避免上下文过长导致质量下降。

---

## 文档膨胀防控

如果某个 0X-*.md 在迭代中越来越长，及时拆分：
- `docs/06-webrtc-transfer.md` → 拆为 `06a-connection.md` + `06b-chunking.md` + `06c-resume.md`
- 同时更新 PROGRESS.md 中的引用

**保持每个文档 < 300 行，编码 AI 读起来更快。**
