# 编码 AI 提示词模板

每次会话只让 AI 读相关文档，避免上下文爆炸。

## 启动会话（开新对话）

```
你是「御坂网络」项目的开发者。React + WebRTC 的 P2P 文件传输 Web APP。

启动步骤：
1. 读 docs/00-overview.md 了解架构
2. 读 docs/PROGRESS.md 查看当前进度
3. 读 CONTRIBUTING.md 了解开发规范与测试纪律
4. 找到「当前会话焦点」未填写或下一个 ☐ 未完成项
5. 告诉我本次计划，等我确认

原则：
- 不要一次读所有文档。按 PROGRESS.md「参考 0X-xxx.md」按需读取
- 完成任务后必须更新 PROGRESS.md（☐ → ☑/◐，记录焦点 / 已知问题 / 决策）
- 不修改无关代码
- 不安装未提及的依赖
```

## 模块开发模板

```
本次任务：实现 [模块名]

请先读：
- docs/PROGRESS.md
- docs/archive/[文档编号]-xxx.md
- docs/archive/01-design-system.md（涉及 UI 时）

开发前：
1. 运行 npm test 确认基线全部通过。
2. 若基线已红，先修基线再开发。

开发中：
3. 新功能必须同步写测试（覆盖 happy path + 至少 1 个边界情况）。
4. 每完成一个子模块，再跑一次 npm test 确认不相互干扰。

完成后更新 PROGRESS.md。
```

## 会话结束

```
本次会话结束。请：
1. 运行 npm test 确认全量通过
2. 更新 docs/PROGRESS.md
3. 5 行内总结完成内容
4. 列出下次会话优先做的 1-3 件事
```

## 调试 / 修 bug

```
出现 bug：[描述]

1. 先写一个能复现该 bug 的失败测试用例。
2. 确认用例确实失败（红灯）。
3. 修复代码，确认用例变绿。
4. 运行 npm test 确认无回归。
5. 更新 PROGRESS.md「已知问题」。
```

## 项目硬约定（偏离时贴这段）

```
项目约定：
1. UI 文案使用 docs/archive/01-design-system.md 术语对照表
2. 颜色/字体/组件用设计 token，禁辉光/扫描线/glitch
3. 服务端不持久化任何数据，全部内存
4. QR/分享链接绝不包含可重复使用的通行码，只携带短时效一次性接入令牌
5. TURN 默认禁用
6. 完成必须更新 PROGRESS.md

测试纪律（硬性）：
7. 修改已有功能前必须先跑 npm test 确认基线通过。
8. 修改完成后必须再次跑 npm test，全绿才能提交。
9. 新增功能必须在同一变更中附带测试用例。
10. 修 bug 必须先写复现该 bug 的失败用例，再修代码。
11. 改动了 client/src/ 或 server/src/ 就必须同步改动对应 tests/。
    未经测试的代码变更会被 CI guard 拦截。
```
